# ぴょんぴょんノート（kaede/）

妹（小2、バンコクのインター校、2027年8月に小3で帰国）のための学習アプリ。兄の「学習ノート」（リポジトリ直下）とは別のアプリで、このフォルダの中だけで完結する。
父親（依頼者）は非エンジニア。報告は日本語で、短く、結論から。

- 公開URL: https://ryonagamatsu.github.io/gakushu-note/kaede/ （きょうの宿題を直接開くのは末尾に `#today`）
- 答え・手書き・採点: 非公開の `RyoNagamatsu/gakushu-data` の `kaede/data/`, `kaede/grades/`（兄と同じ鍵で送る）
- 学習計画と進み具合は非公開の `gakushu-data/kaede/plan/` にある（公開リポジトリには書かない）

## ファイル
- `tools/check_week.py` … 週ファイルの検査（計算の検算、画数の照合）
- `index.html` … アプリ全体。変更したら `./kaede/deploy.sh "説明"` で反映（BUILD と `kaede/version.json` を更新して push）
- `weeks/index.json`, `weeks/<月曜の日付>.json` … 毎週の宿題と土曜テスト
- 書き順データは直下の `../kv/` を共用する。アイコンは白いうさぎ

## いまの段階（2026-10-11 に保護者と決めた）
実力テストのあとで、ひらがなは読むのもあやしい字があり、カタカナはほとんど読めないと分かった。漢字より先に、かなを初歩からしっかりやる。英語は得意（英検4級満点）なので、説明には短い英語を添える。ただしローマ字（アルファベットでかなの音を書くこと）は使わず、音はことばと絵で教える。
1. ひらがな（第1週の火曜〜第2週）: 46字 → にごる音 → 小さい「っ」・のばす音 → 小さい「ゃゅょ」
2. カタカナ（第3〜4週のめやす）: アから1日5字。第4週の後半に、にごる音・小さい字・「ー」。ひらがなの復習（読む・書く）を毎日つづける
3. 漢字（第5週のめやすから）: 小1の漢字を1日2字。手・目だけは第1週の月曜に済み
さんすうは毎日つづける（数字だけで解ける計算が中心。文章題は、かなが読めるようになってから日本語＋英語で少しずつ）。進み具合は `gakushu-data/kaede/plan/progress.json` の `stage` と `kana_next` を見る。土曜テストでかなの読み書きが8割に届かなければ、先へ進まずにその範囲をもう1週やる。

## 週ファイルの形
兄のアプリと同じ基本形（`id`, `n`, `label`, `days[]`, `test`、SECTION は `h`, `note`, `passage`, `grid`, `items`）。ITEM は次のどれか:
```
{"k":"kana","id","ch":"あ","ro":"","ex":["あり","🐜"]}   かな1字。書き順の手本、例のことばと絵、なぞる・かくの2わく（"n":3 で3わく）。ro（ローマ字）は使わない
{"k":"kanji","id","ch","on","kun","st","ex":[[ことば,よみ]…],"tip","rq":[ことば,よみ],"wq":[ひらがな,漢字]}
{"k":"fill","id","tpl":"🐶　{}ぬ","b":[{"a":["い"],"w":4}],"pts":1}      わくに手書き。計算は "b":[{"a":["27"],"t":"num","w":6}]
{"k":"choice","id","q":"🐶","opts":["いぬ","ねこ","とり"],"a":"A","pts":1}   既定のラベルは ABCD（かな段階では アイウ を使わない）
{"k":"ink","id","q","h":460,"cls":"s","model":"手","pts":1}   手書きのわく。scratch:true で計算スペース
{"k":"long","id","q","rows":3,"model","pts":0}
{"sub":"小見出し"}
```
- `wd` は「げつ・か・すい・もく・きん」（並び順の記録だけで、画面には出ない）。`label` は「<n>w」（例「2w」。アプリは n から「2w」「1にちめ〜5にちめ」「テスト」と表示する。カレンダーの日付は本人に見せない）。1日 `min:20`
- 同じ日の中で `id` を重複させない。`【　】` で囲むと黄色のマーカー
- 計算の答えは必ずプログラムで検算する。漢字の画数は `../kv/` と合わせる。どちらも `tools/check_week.py` が見る

### かなの段階の1日（見本は `weeks/2026-10-19.json`。作り方は `tools/kana_days.py` と `tools/example_gen_week_2_pictures.py`）
**ローマ字は使わない**（2026-10-12、保護者の希望。英語を中心に習っている本人には、アルファベットからかなは混乱のもと）。音は、ことばと絵（絵文字）で教える。`kana` の `ro` は空にする。
1. かな 5〜10字（`kana` の section、`grid:true`）: 書き順の手本、例のことばと絵（`ex: [ことば, 絵文字]`）、なぞる・かく
2. ふくしゅう: 前の日の字のことばの絵を見て、あうことばを3つから選ぶ7問（`pick_word`）
3. かけるかな: 絵を見て、ことばの中のぬけた字（その日の字）を書く6問（`missing`）
4. ことば: ことばを読んで、あう絵を3つから選ぶ5問（`pick_pic`）＋絵を見てことばを全部書く2問（`write_word`）
5. さんすう: 計算12問（数字で答える fill。右に計算らんが自動で出る）
6. にがて れんしゅう（見出しは「にがて れんしゅう」）: 12〜15問。progress の `weak_kana` と `weak`、前の週のテストと宿題でまちがえた字・単元（`vals.self` が 0、`vals.aic` の ok が false）だけから出す。かなは読む（`pick_word`／`pick_pic`。見まちがえやすい相手の字を選択肢に）と書く（`missing`／`write_word`）を半分ずつ、さんすうは苦手な単元の類題。苦手が少ないときは、前の週までに習った字の読み書きで埋める
- 1日50〜60問（2026-10-21、保護者の希望で以前の約1.5倍に。実際は1日5〜8分で終わっていたため。ふやした分は苦手分野に回す）。かかった時間（`vals.el`）が25分を超える日が続いたら、6. を減らす。「よめるかな」（字を見てローマ字を選ぶ）はやめた。入れない
- `note` は日本語（ひらがなの分かち書き）のあとに改行して、かっこ書きで短い英語。英語の中にもローマ字（ka, ga など）を書かない
- ことばは、その日までに習った字だけで書けて、絵文字で表せるものにする。絵がまぎらわしいことばは使わない
- カタカナの段階でも同じ形。ひらがなとの対応（あ → ア）は、ひらがなのことばとカタカナのことばを並べて見せる。ことばは外来語（パン🍞、ミルク🥛、バナナ🍌）
- 土曜テスト（20分）: どれかな（絵→ことばを選ぶ）10、かけるかな（ぬけた字）10、ことばを全部書く4、計算9〜10。月〜金の内容だけから出す
- サッカー、バレーボール、ワールドカップの題材は使わない

## アプリのしくみ
- 先へ進める（カレンダーには合わせない）: 開いている週は5日分が一度に開く。5つとも答え合わせまで終えるとテストが開く。テストを出すと次の週が開く（次の週のファイルがあれば）。日付や曜日で開くことはない。判定は `lockInfo` と `weekOpen`。いちばん古い週はいつも開いている
- テストが開いてから出すまでは、出しおわった宿題（赤字の答えが見える）は開けない
- `#today` をつけて開くと、次にやる宿題（`nextTask`）が直接開く
- 宿題やテストを1つ出すと、白いうさぎ「ぴょんぴょん」がにんじんを1本食べる。5日とも当日までに出した週は＋2本。0/3/7/15/30本で育つ（`STAGES`）
- こたえあわせ: 宿題を出すと、そのまま答え合わせの画面になる。赤字の答えを見て本人が問題ごとに ○× を押し、× の問題はその場でもう一度書く（手書きは `<キー>.r` のわく、選択問題は正しい答えを選び直す＝`vals.rc`）。全部終えて「こたえあわせを おわる」を押すと `vals.rev=true` になり、にんじんがもらえる。記録は `vals.self`（キー→1か0）。テストには答え合わせはない
- 計算コーナー: 数字で答える fill の問題（`b[0].t` が `num` で、`work` がないもの）には、右側に問題ごとの計算らんが出る（キーは `<id>.c`。採点や答え合わせの対象ではない）
- ポイント（おこづかい用）: 1週間の上限は50。宿題は1日5（出して3＋答え合わせと書き直しを終えて2）、5日とも5ならボーナス5、土曜テストは8割以上15・6割以上10・未満5（採点がすむまでは5）、ていねいボーナス5（保護者がつける）。兄のアプリと同じ決まり。計算は `weekPts`。ホームに週ごとの点と合計が出る
- ぼうけん（育てる・先が気になる仕かけ。`rpg()`、`advHTML`、`openBoxes`）: 保存するのは「たからばこを開けたか」（`vals.box`）だけで、あとは答えのデータから毎回計算する
  - レベル: 宿題やテストを終えるたびに経験値（10＋正解数の半分、テストは＋10）。必要な経験値は少しずつ増える
  - すがた: にんじん 0/3/7/15/30本で変わる。3段階目からは、その時点までの「こくごの正解率」と「さんすうの正解率」の差で3通りに分かれる（こくごが8ポイント以上高い＝めがね→まほうつかい→ほしのけんじゃ、さんすうが高い＝はちまき→ゆうしゃ→そらとぶゆうしゃ、差が小さい＝リボン→おはな→プリンセス）。次のすがたは画面では「？？？」にして見せない（`FORMS`）
  - たからばこ: 宿題やテストを1つ終えるたびに1つ。中身は40種類から、同じものが出ないように決まる（テストで8割以上なら、きらきらの10種類から）。本人がボタンで開ける。開けたものは「ずかん」にたまる（`ITEMS_C`、`ITEMS_R`）
  - ちず: 1週間が1つの場所（`AREAS`、12週で一巡）。宿題1つで1マス進み、最後のとびらがテスト。次の場所の名前は見せない
  - うさぎを押すと、はねてひとこと話す。最後に終えてから時間がたつと「おなかが すいたよ」と言う（ペナルティはない）
  - 自動作業では触らない。たからものや場所を足すときは、ひらがな・カタカナの名前にする
- まめちしき: 宿題の答え合わせを終えるたびに、体操のコツ（`TIPS_G`）とうさぎの小話（`TIPS_R`）が1つずつ、その場で1回だけ小さな窓に出る（ホームには残さない。保護者の希望）。各45個で、同じものは一巡するまで出ない（`vals.tip` が番号）。1週5個なので9週で一巡する。足すときは、ひらがなとカタカナだけの分かち書きで、体操は安全なやり方だけ、うさぎは確かな事実だけを書く
- 宿題は「出して、答え合わせも終えた」ときに終わり（`isFinId`）。土曜テストが開く条件も、にんじんの数もこれで数える
- 見た目は明るいピンクのかわいいデザインで固定（暗い配色は使わない。iPadがダークモードでも明るいまま）。サッカー・バレーボール・ワールドカップの題材は使わない
- ポイントのさいふ: ホームに「もらった・つかった・のこり」とバーツ換算（1ポイント＝`rate` バーツ、保護者用画面で設定。既定1）。本人が「ポイントを つかう」で使ったポイントと用途を記録する。保存先は `gakushu-data/kaede/data/wallet.json`（`vals.log` に {id,t,pts,what,rate}、`vals.rate`）。取り消しは保護者用画面から。自動作業では触らない
- 手書きのAIチェック: 保護者用画面に Anthropic の API キーを入れると（`localStorage` の `gk2.akey`。リポジトリには書かない）、宿題やテストを出した直後に、手書きの答え（かな・漢字の読み書き、空らん、式、記述）をまとめて Claude API へ送る（`aiKeys`→`inkSheets` で #n を付けた画像にして40問ずつ）。結果は `vals.aic[<キー>]`（ok, read, why, pts）。宿題では本人の○×ボタンのとなりに「AI：○／×（理由）」の案を出すだけで、○×は本人が押す。テストでは `grades.o`/`grades.m` に入れる（既にあれば入れない）。保護者用画面の「この課題をAIで採点する（やり直し）」で全部やり直せる。**土曜テストの採点で**: `grades` の値が `vals.aic` の ok/pts と同じならAIがつけたものなので、画像を読んで明らかに違うときは直してよい。違う値なら親が直したので触らない
- テスト提出直後の採点（兄のアプリと同じ）: 「出す」のあと、AIの手書きチェックを最大2分半待ち、点数をその場で本人に見せる。次の週がまだないときは「この けっかを 見て、つぎの しゅうの しゅくだいを つくります。1〜2じかんで ひらきます。」と出す。AIの返事が読めない・混んでいる（429/5xx/529）ときは自動で2回までやり直し、それでも失敗したら、アプリを開いている間は1分ごとに `aiCatchUp` が再試行する。`aicErr` には失敗時の返事の頭80字が入る
- オフライン: 1つ上のフォルダの `../sw.js`（兄のアプリと共用）がアプリ本体・`weeks/`・`../kv/`・Webフォントを端末に保存する。ネット優先なので公開した更新は今までどおりすぐ届く。オフライン中に出した分は端末に残り、ネットが戻ると自動で送信・AIチェックする（`vals.aiWait` が目印）。翌週分はネットのあるところで一度開かないと入らない。くわしくは上のフォルダの CLAUDE.md
- 端末内の保存キーは `gk2.*`（兄のアプリは `gk1.*`。混ぜない）

`gakushu-data/kaede/plan/plan.md`（全体の計画）と `gakushu-data/kaede/plan/progress.json`（習った漢字、扱った単元、弱点、次にやること）。成績にかかわることは公開リポジトリに書かない。

## 毎日の流れ（バンコク時間の6時〜21時に1時間ごとに動く）
父親の希望は「テストを出したらすぐ採点し、その採点結果をもとに次の週を作る」こと（兄のアプリと同じ）。本人は先へ進めるので、週IDは実際の日付より先に進むことがある。「最新の週」＝ `kaede/weeks/index.json` の最後の週 L。
1. `gakushu-data` を pull。L のテスト（`kaede/data/w<L>-t.json` の `vals.done`）が提出ずみでなければ、何もしないで終わる（通知も出さない）
2. 提出ずみで、progress.json の `tests` に L の結果（Claude採点）がまだなければ、下の「土曜テストの採点」をする（アプリのAIの点を見直して確定）。AIの採点がまだ終わっていない（`vals.aicq` が残っている）ときも、待たずに自分で採点してよい
3. 提出ずみで、次の週（IDは L＋7日。実際の日付とは関係ない）がまだなければ、2の結果を反映して下の「1週間の作り方」で作って公開する。日付や曜日では判断しない
4. 本人が始めている週（L やそれより前）の週ファイルは書き換えない。公開の直前に `git pull --rebase` して次の週がもうできていたら、自分の分は公開しない

## 1週間の作り方
1. `gakushu-data/kaede/plan/` の plan.md と progress.json を読む。直近の宿題とテスト（`kaede/data/`, `kaede/grades/`）を見る。手書きは `python3 tools/render_ink.py <dataファイル> <出力dir>` で画像にして読む（直下の tools を使う）
2. 作る週のファイルが既にあれば何もしない
3. 内容は上の「いまの段階」「週ファイルの形」と plan.md の順に。かなの段階では progress の `kana_next` から、漢字の段階では `kanji_next` から。さんすうは `math_next` から。かかった時間（`vals.el`）が25分を超える日が続いたら量を減らす（まず「にがて れんしゅう」から）
   - **前の週の結果に合わせる（必ずやる）**: 作る前に、前の週のテストを1問ずつ（正解・不正解・空らん）と、宿題で本人が × をつけた問題（`vals.self` が 0）、AIチェックの結果（`vals.aic` の ok が false）を一覧にする。まちがいを「どの字・どの単元」と「まちがい方」に分ける（例: 「さ」と「き」を読みちがえる／「ぬ」と「め」を書きまちがえる／字は合うが鏡文字／にごる音の点がない／小さい「っ」をぬかす／くり下がりで小さい数から引く／九九の7のだんだけ）。そのうえで:
     - まちがえたかなは、次の週の毎日の「ふくしゅう」（読む）と「かけるかな」（書く）に必ず入れ、月・火の2日は `kana` のなぞり書きにももう一度入れる。見まちがえやすい相手の字（さ・き、ぬ・め、わ・ね・れ、は・ほ、シ・ツ、ソ・ン など）を、えらぶ問題のまちがいの選択肢に入れる
     - まちがえた計算は、数字を変えた類題を次の週の月・火に2〜3問ずつ入れる。まちがい方に合わせて note の説明と「れい」を書き直す
     - その週のかなの読み書きがテストで8割未満なら、新しい字へ進まずに同じ範囲をもう1週やる（ことばと問題は変える）。8割以上なら次へ進み、まちがえた字だけ復習に残す
     - さんすうは、正答率6割未満の単元を次の週も毎日3〜4問、6〜8割は週に2日、8割以上は週1回に減らして次の単元へ進む。2週つづけて6割未満なら1つ前の段階にもどす
     - 次の週のテストに、前の週にまちがえた字・単元の問題を5問ほど入れる（定着したかを見るため）
     - 父親への報告に「前の週にまちがえたこと → 今週こう入れた」の対応を2〜4行で書く。progress.json の `weak`（まちがえた字は1字ずつ）と `tests` を更新する
4. `python3 kaede/tools/check_week.py kaede/weeks/<id>.json` を通す（計算の検算と画数の照合）
5. `kaede/weeks/index.json` にIDを足し、`./kaede/deploy.sh "だいNしゅうの宿題を追加"` で反映。progress.json を更新して gakushu-data に push
6. 父親への報告: その週のねらいを、直近の結果との対応で3〜5行

## 土曜テストの採点
1. `tools/render_ink.py` で画像にして読む。読めない字は「要確認」として報告し、点はつけない
2. `gakushu-data/kaede/grades/w<週ID>-t.json` に書く: `{"t":<今のUNIXミリ秒>,"m":{"<inkのid>":点,"<fillのid>.w":式の点},"o":{"<fillのid>.<空らん番号>":true/false},"read":{}}`。親がつけた採点がある項目は上書きしない。`t` は既存より大きくする。`neat` は触らない
3. commit して push（push の前に必ず `git pull --rebase`。兄の作業と同じリポジトリなので、`kaede/` の外は変更しない）
4. 点数、まちがいの傾向、次に回す単元を progress.json に書き、父親に報告
